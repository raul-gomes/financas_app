# Dashboard Metrics Expansion

## Overview

Expand the Financial dashboard with new metrics and improve existing chart interactivity. The goal is to give the user a comprehensive view of expenses, investments, and financial health — all visible at a glance without excessive scrolling.

## Features

### Feature 1: Monthly Goal Line on Daily Chart

**Problem**: When the user flips the yearly chart to see daily data for a month, the monthly goal line (displayed on the annual chart) disappears, removing important context.

**Solution**: Pass `monthlyGoal` to `D3DailyChart` and render a horizontal dashed goal line identical to the one in `D3BarChart`:

- `stroke-dasharray` line across the full chart width
- Label at the right end: `Meta: R$ 3.000`
- Same color (`#ef4444`) and style as the yearly chart

**File**: `frontend/src/components/D3DailyChart.tsx`

### Feature 2: Highlight Selected Month in Yearly Chart

**Problem**: After clicking a month to see its daily breakdown, there is no visual indicator of *which* month was selected when viewing the yearly chart.

**Solution**: Accept a `selectedMonth` prop in `D3BarChart` and style that month's bars differently:

- All three bars (income, expense, investment) in the selected month get `opacity: 1` and a slightly darker stroke
- Other months remain `opacity: 0.8`
- If no month is selected, all bars render uniformly

**File**: `frontend/src/components/D3BarChart.tsx`

### Feature 3: Cartão de Crédito — Limit Usage Bar

**Problem**: The credit card card shows the total spent but provides no context about how much of the available limit was used.

**Solution**:

1. **Settings (Limits page)**: Add a "Limite Cartão de Crédito" field alongside the existing monthly global limit.
2. **Credit card card (FinancialDashboard)**: Add a thin progress bar below the value showing usage percentage:
   - `▓▓▓▓▓▓░░░░ 52%`
   - Color shifts as usage increases: green (> 30% remaining), yellow (< 30%), red (over limit)
   - Tooltip on hover: "Limite: R$ 4.700 · Disponível: R$ 2.250"

**Files**:
- `frontend/src/pages/Limits.tsx` — new input field
- `frontend/src/components/FinancialDashboard.tsx` — update credit card card

### Feature 4: Parcelas a Pagar Card

**Problem**: The user has installment purchases but no visibility into future commitments.

**Solution**: Add a new metric card showing total future installment payments.

**Layout**: 4th card in the metrics row (after Pix, Crédito, Débito):

```
┌──────────────────────────────┐
│  💳 Parcelas a Pagar          │
│  R$ 4.200                     │
│  8 parcelas · 3 transações    │
└──────────────────────────────┘
```

- Value: sum of all `(total_parcelas - parcela) * valor_parcela` for transactions with `total_parcelas > 1`
- Subtitle: "X parcelas · Y transações"
- Clicking opens a quick list of the installment items

**File**: `frontend/src/components/FinancialDashboard.tsx`

### Feature 5: Gastos Fixos vs Variáveis

**Problem**: The user cannot distinguish between recurring fixed expenses and ad-hoc variable spending.

**Solution**: Classify transactions as **fixas** (generated from `ContaRecorrente` — recurring bills) vs **variáveis** (ad-hoc), and show a horizontal stacked bar with values.

**Classification logic**: A transaction is "fixa" if it has the `conta_recorrente_id` field populated (i.e., was generated by the recurring bills system). All others are "variáveis".

**Layout**: Replaces one slot in the bottom 2×2 grid (see Layout section below).

```
┌──────────────────────────────┐
│  📋 Gastos Fixos vs Variáveis │
│                               │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░  │
│                               │
│  Fixos:    R$ 2.100 (65%)    │
│  Variáveis: R$ 1.100 (35%)   │
│                               │
│  (baseado em 8 contas         │
│   recorrentes ativas)         │
└──────────────────────────────┘
```

**Files**:
- `frontend/src/components/FinancialDashboard.tsx` — new section
- Backend — add `conta_recorrente_id` field to Transaction model (see Data section)

### Feature 6: Settings — Differentiate PF/PJ Monthly Limits + Cartão Limit

**Problem**: The "Limite Mensal Global" is a single value, but the user needs separate limits for PF (pessoa física) and PJ (pessoa jurídica), plus a credit card limit.

**Solution**: Replace the single "Limite Mensal Global" card in `/limits` with three fields:

```
┌──────────────────────────────────────┐
│  💰 Limites Globais                   │
│                                      │
│  Limite Mensal PF:    [ R$ 3.000 ]   │
│  Limite Mensal PJ:    [ R$ 5.000 ]   │
│  Limite Cartão Crédito:[ R$ 4.700 ]  │
│                                      │
│  Usados como referência nos gráficos │
│  e no card de Cartão de Crédito.     │
└──────────────────────────────────────┘
```

**Backend storage**: Three entries in the `categorias` table with special names:
- `Mensal PF` (natureza: pf)
- `Mensal PJ` (natureza: pj)
- `Limite Cartao Credito` (natureza: mensal)

The `meta_mensal` value in the API response is determined by the currently selected entity type filter (PF → Mensal PF limit, PJ → Mensal PJ limit).

**Files**:
- `frontend/src/pages/Limits.tsx` — three inputs instead of one
- Backend — update `dashboard.py` repository to read the correct `meta_mensal` based on natureza

## Dashboard Layout (Updated)

```
┌────────────────────────────────────────────────────────────┐
│ [Pix] [Cartão Crédito + %] [Débito] [Parcelas a Pagar]    │  ← 4 cards
├────────────────────────────────────────────────────────────┤
│                    📊 Bar Chart (max-h 420px)               │
├──────────────────────────────────┬─────────────────────────┤
│     📈 Entradas do Período      │  📋 Gastos por Categoria │
├──────────────────────────────────┼─────────────────────────┤
│         📋 Gastos Fixos vs Variáveis (full width)          │
└────────────────────────────────────────────────────────────┘
```

The bottom section is organized as:

| Row | Content |
|-----|---------|
| 1 (2-col) | IncomeChart (left) \| CategoryBreakdown (right) |
| 2 (full) | Gastos Fixos vs Variáveis (single card, full width) |

**Parcelas a Pagar** lives exclusively in the metrics row as card #4. Clicking it opens a small popover/dialog with the installment detail list — keeping the dashboard clean while still allowing drill-down.

## Data Changes

### Backend

**Transaction model**: Add optional `conta_recorrente_id: int | null` foreign key to link transactions back to their recurring bill source.

**Categorias table**: Add three special entries (seeded or on first access):
- `Mensal PF` — monthly goal for PF
- `Mensal PJ` — monthly goal for PJ  
- `Limite Cartao Credito` — credit card limit

**Dashboard endpoint**: Update `meta_mensal` logic to return the limit matching the `natureza` filter:
- `natureza=pf` → use `Mensal PF` limit
- `natureza=pj` → use `Mensal PJ` limit
- `natureza=all` → sum of both (or highest)

### Frontend Types

No new types needed. Existing `Transaction`, `CategoryBreakdown`, `YearlyData` cover all data needs.
