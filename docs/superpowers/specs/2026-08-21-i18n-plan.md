# Internacionalização (i18n) — pt / en / es

**Data:** 2026-08-21
**Status:** Approved (aguardando execução)

## 1. Objetivo

Tornar o frontend trilíngue (**pt-BR**, **en-US**, **es-ES**) com detecção automática
do idioma do navegador, persistência da escolha do usuário e seletor manual na UI.
Nada está em produção — a migração pode ser feita de uma vez, sem período bilíngue.

## 2. Decisões

| Decisão | Escolha | Justificativa |
|---|---|---|
| Biblioteca | `react-i18next` + `i18next` | Padrão de mercado p/ React SPA; hooks + pluralização + interpolação |
| Detecção | `i18next-browser-languagedetector`, ordem `localStorage → navigator` | Respeita idioma do SO/navegador na 1ª visita; depois guarda a escolha do usuário. Sem geo-IP no servidor (desnecessário e caro) |
| Fallback | `pt` | App nasceu em PT; chave ausente em en/es cai em PT sem quebrar |
| Moeda | **BRL fixo** (constante `CURRENCY`), locale numérico dinâmico | App financeiro brasileiro usado no exterior: valores continuam R$, mas `1.234,56` ↔ `1,234.56` segue o idioma |
| Dados do BD | **Fora do escopo** (categorias/contas seeded continuam em PT) | Traduzir conteúdo dinâmico exigiria tabela de traduções no backend — decisão futura separada |
| Namespaces | Um único `translation.json` por idioma no início | Simples; dividir depois se os arquivos crescerem |

## 3. Estrutura de arquivos

```
app/frontend/src/
├── i18n/
│   ├── index.ts                    # init i18next + detector
│   └── locales/
│       ├── pt/translation.json     # fonte da verdade (PT atual do app)
│       ├── en/translation.json
│       └── es/translation.json
├── components/
│   └── ui/language-switcher.tsx    # seletor (dropdown simples com bandeira/sigla)
└── lib/
    └── format.ts                   # passa a ser locale-aware (§5)
```

Registro no `main.tsx`: `import './i18n'` antes de `<App />`.
`<html lang>` atualizado via `document.documentElement.lang = lng` no change.

## 4. Convenções de chaves

- Hierarquia por domínio: `nav.*`, `recorrentes.*`, `metas.*`, `compras.*`,
  `extrato.*`, `settings.*`, `dialogs.*`, `charts.*`, `common.*`
  (`common.save`, `common.cancel`, `common.delete`, `common.confirm`...)
- Interpolação: `"parcelasCanceladas": "Conta desativada. {{total}} parcelas futuras canceladas."`
- Pluralização nativa i18next: chaves `count_one` / `count_other` via `t('x', { count })`
  (pt/en/es seguem o mesmo esquema singular/plural)
- Nunca concatenar strings traduzidas — sempre frase completa na chave

## 5. `lib/format.ts` locale-aware

```ts
const LOCALES = { pt: 'pt-BR', en: 'en-US', es: 'es-ES' } as const;
export const CURRENCY = 'BRL';
// formatter recriado quando i18n.language muda (listener ou memo por language)
```

`formatCurrency`, `formatDate`, `formatPercent` passam a usar o locale corrente.
Ponto central único — nenhum call site muda assinatura.

## 6. Fases de execução

| # | Fase | Arquivos | Notas |
|---|---|---|---|
| 0 | Dependências | `package.json` | ✅ já instaladas no container (`npm install` executado) |
| 1 | Infra i18n | `src/i18n/**`, `main.tsx` | init + detector + fallback; smoke test com `i18n.changeLanguage` |
| 2 | Seletor de idioma | `ui/language-switcher.tsx`, `SidebarPanel` (+ `AppLayout`) | persistência automática via localStorage; atualiza `<html lang>` |
| 3 | Formatação | `lib/format.ts` | locale dinâmico; validar R$ vs números nos 3 idiomas |
| 4 | Layout/nav | `AppLayout`, `SidebarPanel` | labels de menu, títulos |
| 5 | Pages | `Dashboard`(se houver texto), `Transactions`, `RecurrentBills`, `BankExtract`, `Settings`, `Investments`, `Limits` | headers via `PageHeader`, empty states via `EmptyState` (strings vêm dos callers) |
| 6 | limits/* | `LimitsTab`, `RecorrentesTab`, `ComprasTab`, `MetasTab`, `ContaForm` | inclui toasts de sucesso/erro |
| 7 | Dialogs (11) | `Add/EditTransactionDialog`, `Add/EditRecurrentBillDialog`, `Add/EditInvestmentDialog`, `DuplicateDialog`, `BankBreakdownModal`, `PluggyInfoDialog`, `ExtratoUploadModal`, `ExtratoDialog` | placeholders, labels, validações, toasts |
| 8 | Charts + listas | 7 gráficos D3 (tooltips inline "Limite:", "Faltam..."), `TransactionList`, `MetasList`, `ComprasList` | `useTranslation()` direto nos componentes de chart; revisar `date-fns` (locale) |
| 9 | Validação | — | `tsc --noEmit`; varredura final `grep` por literais PT remanescentes; smoke test manual trocando os 3 idiomas |
| 10 | Docs | `components.md`, `arvore_arquivos.md`, `AGENTS.md` | LanguageSwitcher no catálogo; regra "string nova sempre via t()" |

Ordem proposital: infra → pontos centrais (format/layout) → folhas (telas).
Cada fase termina com `tsc` verde antes da seguinte.

## 7. Pontos de atenção

1. **D3 tooltips** usam strings dentro de template literals HTML — traduzir antes de montar o `.html()`.
2. **date-fns**: `ComprasList` importa `format` — avaliar importar `ptBR/enUS/es` de `date-fns/locale` onde houver nomes de mês/dia visíveis.
3. **Defaults de componentes** (`ConfirmDialog.confirmLabel = "Confirmar"`) devem receber valores já traduzidos pelos callers, ou virar chaves internas — decidir na fase 7 (preferência: callers passam `t('common.confirm')`).
4. **`AnimatedNumber`/`Settings.fmt`** ficam como estão (apenas número), mas herdam o locale novo do `format.ts` automaticamente.
5. **Teste de detecção**: DevTools → Sensors → Language, ou `localStorage.setItem('i18nextLng', 'en')`.
6. Não traduzir: códigos de banco, métodos de pagamento armazenados (`pix`, `credito` — dados), rotas da URL.

## 8. Critérios de aceite

- [ ] Primeira visita respeita o idioma do navegador; troca manual persiste após reload
- [ ] Os 3 idiomas renderizam todas as telas sem literais PT órfãos nas superfícies das fases 4–8
- [ ] Valores monetários/datas formatados conforme o idioma (moeda sempre BRL)
- [ ] `tsc --noEmit` verde; nenhuma regressão funcional (fluxos de criar/editar/excluir testados)
- [ ] Docs atualizadas na mesma mudança
